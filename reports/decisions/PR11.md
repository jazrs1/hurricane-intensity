**Before `launch` can run (PR B or a small follow-up):**
- **ASK A (med): needs you, because it adds to the pre-registration.**
  - (a) **Tie tolerance.** GPU noise (~1e-5 kt) could make the re-validated pick differ from train.py's pick when two epochs are within noise. That would stop the launch after training time is spent. Rule: accept the mismatch when the two values differ by < 1e-4 kt and both round to the logged values, and record it in the manifest. It can't be exploited, since both picks are within float noise.
  - (b) **A written abort procedure.** Any stop mid-launch (that, or an out-of-memory error) can't be resumed, by design. Pre-register what a stop means, how completed runs are kept, and that the remaining runs restart in fresh folders under a new decisions entry.
  - Forcing deterministic GPU kernels was rejected: it would change train.py and the configuration.
- **ASK B (med-low; coordinator will add it):** launch only from a commit that is merged and pushed to phase2-experiments, so a local unreviewed commit can't fill the constants and launch.
- **ASK C (low-med; coordinator will add it):** refuse to launch from a worktree (ROOT must be the main checkout). Optionally, refuse if no GPU is available, since a CPU fallback would silently take hours.
- **scipy (low; coordinator will add it):** add `scipy==1.18.1` to requirements.txt. It's only present today via metpy.
- **2021_storms.txt (low; coordinator will add it):** an old UTF-16 grep output tracked at the root. Register it in the list registry as an "example".
