## The problem

Every `check.py --e2e` case left a %LOCALAPPDATA%\Temp\hc_e2e_* folder holding its test crop. An unclosed `np.load` kept the crop locked on Windows, and `rmtree(ignore_errors=True)` then skipped it silently. 42 folders had built up; all are deleted, per your yes.

## What it does

- **Closes both crop reads** (`with np.load(...)`).
- **remove_tree() never ignores errors.** It removes the temp folder whether the case succeeds or fails partway, then confirms it's gone.
- **A folder that can't be removed fails the case,** naming the path. It never passes silently while leaking.
- **If the case itself failed,** its original error is kept, with cleanup problems attached as notes and printed as "ALSO: …". This also fixes an old bug where a data/ change found during cleanup replaced the case's own error.
- **A warning at the start of `--e2e`** for any hc_e2e_* folder left by an earlier killed run (a hard kill skips cleanup). It's a warning only; nothing is deleted.
- **Test disk use:** the test model is hard-linked instead of copied, which cuts pytest temp space per run from 299 MB to 43 MB.
