## Item 1: the design amendment (cc3d537, 2 lines), and why it needs your yes

**What it changes:**
- **Before (approved in PR #31, §4):** unfreeze refuses if the "v2 Atlantic ensemble frozen" entry is in the committed decisions log **either on the branch checked out (HEAD) or on GitHub** (origin/phase2-experiments, after a fetch).
- **After:** unfreeze refuses if the entry is in the decisions log **on GitHub**. The entry's exact first-line form is also fixed: `YYYY-MM-DD, HH:MM. v2 Atlantic ensemble frozen…`.

**Why:**
- Unfreeze can only run on the freeze branch, and that branch's own commit always carries the entry under review. So the HEAD half would refuse every unfreeze, and the design's own unfreeze procedure could never run.
- The GitHub half is the real protection: once the freeze PR merges, unfreeze is refused for good.

**Facts to weigh:**
- **Neither half ever worked.** As first shipped, the driver looked for a heading format the decisions log doesn't use (D2), so neither half could fire. The amendment makes the GitHub half work, and removes the HEAD half.
- **The HEAD half was hc-adversary's own suggestion** in its PR #31 review (31b, finding B). In item 34 it said that suggestion was wrong for the freeze branch. So the reviewer is partly correcting itself here.
- **Still blocks unfreeze after the amendment:**
  - the members file on GitHub (the normal merge);
  - the entry on GitHub;
  - any H-EP or clean-test output.
- **Given up:** only the check against the freeze branch's own unmerged entry, which by design is the one under review.
- **This is a loosening of approved text, so it is yours to approve.** hc-adversary confirmed it is exactly the needed change, and that today the entry does not exist on GitHub, so unfreeze isn't blocked in advance.
